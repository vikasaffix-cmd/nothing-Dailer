## 1. Must fix before submission (in priority order)

Each fix below changes code. Ask the user before making any of them. Only the Release build session runs Gradle.

| # | Severity | Problem | Proposed fix |
|---|---|---|---|
| 1 | **Blocker** | `targetSdk = 35` / `compileSdk = 35`. Since **31 Aug 2026**, Play rejects new apps and updates that don't target **Android 16 (API 36)**. Google gave extensions until 1 Nov 2026, but only to apps that already existed. | Set `compileSdk = 36` and `targetSdk = 36` in `app/build.gradle.kts`. Then handle the Android 15/16 behaviour changes: edge-to-edge is forced and can't be opted out of (MainActivity never calls `enableEdgeToEdge()`, so check that the keypad, the in-call controls and the Recents headers aren't drawn under the status or navigation bars); predictive back (Compose `BackHandler` is fine); on screens 600dp and wider, orientation and resizability locks are ignored. Re-test the incoming-call and lock-screen flows. |
| 2 | **Blocker** | **Call log and phone permissions are requested before the app is the default dialer.** `MainActivity.onCreate` → `requestRequiredPermissions()` asks for READ/WRITE_CALL_LOG (plus CALL_PHONE, READ_PHONE_STATE, RECORD_AUDIO, READ_CONTACTS) on every first launch. The Play policy says an app "must be actively registered as the default … Phone … handler **before prompting** users" for Call Log permissions, and must stop using them once it is no longer the default. Reviewers test this, and it's the most common reason dialers get rejected. | Run the default-dialer role request first. Ask for the call log permissions only once `isDefaultDialer` is true; on Android 10+ the role usually grants them already. While the app is **not** the default dialer, Recents, the widget's recent calls, the keypad suggestions and missed-call handling should show a "Set NoDialer as default" state instead of reading the call log, even when the permission is still granted. |
| 3 | **Blocker** | **RECORD_AUDIO is requested at launch**, before the user has turned on Auto call recording. Asking for a sensitive permission with no context goes against the User Data policy's request-in-context rule, and reviewers flag it. | Remove RECORD_AUDIO from the launch list. Ask for it when the user turns on **Auto call recording**, after a short in-app disclosure. Draft text is in [permission-declarations.md](play-console/permission-declarations.md#prominent-disclosure-for-call-recording). |
| 4 | **High** | **`android:showWhenLocked="true"` and `turnScreenOn` are set on MainActivity in the manifest**, so the whole app (Recents, Contacts, Recordings, Settings, call notes) can be opened over the lock screen without unlocking. That is a privacy hole, and a reviewer may treat it as a security issue. | Remove both attributes from the manifest. Call `setShowWhenLocked(true)` / `setTurnScreenOn(true)` only while a call is ringing or active, and set them back to false when the call ends, or move the in-call UI into its own activity. |
| 5 | **High** | **Play Console declarations are missing.** Without them the release is blocked at review: the Call Log permission declaration (default Phone handler), the foreground service declarations for `microphone` and `phoneCall` (each needs a **video link**), the `USE_FULL_SCREEN_INTENT` declaration (calling app), the Data safety form, and a **public privacy policy URL**. | Drafts are in `docs/play-console/`. Record the two FGS demo videos (unlisted YouTube is fine). Host the privacy policy at a public URL: the user decides where. |
| 6 | **High** | **The trademark "Nothing" appears in user-visible text.** `font_dot_matrix_summary` = "Nothing Phone–inspired font by Dmitriy Sychiov (default)" (plus its hi/mr translations). "Nothing" and "Nothing Phone" are Nothing Technology's trademarks. Combined with the red `#D71921` and the dot-matrix look, this invites an impersonation or IP complaint. The "NoDialer" name is far enough away, but don't use "Nothing" in the listing, the screenshots or the UI. | Change the string to e.g. "Dot-matrix font by Dmitriy Sychiov (default)" and update the hi/mr files. Credit the font in the listing and the licence screen by its **author**: "dot font by Dmitriy Sychiov (SIL OFL 1.1)". The OFL allows renaming files, and the font has no Reserved Font Name. Keep the code constant `NothingRed` as it is (it's never shown to users) or rename it to `AccentRed`. |
| 7 | **Medium** | **`MANAGE_OWN_CALLS` is declared but unused**: there's no self-managed `ConnectionService`. Unused permissions draw reviewer questions. | Remove it from the manifest. |
| 8 | Low | **`phoneCall` foreground service type, now on two services.** `CallService` (the InCallService) has `foregroundServiceType="phoneCall"` and calls `startForeground` with the ongoing CallStyle notification (the status-bar call chip) while a call is up. That is the textbook use for the default dialer. `CallRecordingService` still declares `microphone|phoneCall` and reuses that notification. | One `phoneCall` declaration covers both, with the CallService description below. The recording service's `phoneCall` is now easy to explain because it shares the call's notification and lifetime. Optional tidy-up: drop `phoneCall` from CallRecordingService if recording still works with `microphone` alone. |
| 9 | ✅ **Done** | **Auto Backup is now set up deliberately** (Backup & restore session). Every SharedPreferences file except `dialer_widget.xml` is backed up, including call notes, the blocklist and rules, spam reports, network caller names, speed dial, settings and the lookup URL, plus `filesDir/custom_display_font`. Cloud backup only runs end-to-end encrypted (`disableIfNoEncryptionCapabilities=true`; `clientSideEncryption` on Android ≤ 11). Device-to-device transfer copies the same set. Recordings, voicemail transcripts (`voicemail_transcripts.xml`) and caches are never included. Call pill and smart-SIM settings are included. There's also a manual Settings → Backup & restore export, saved to a file the user chooses; recordings and the lookup URL are included only if the user picks them. | Nothing left to do. The privacy policy now describes this. Data safety doesn't change: backup to the user's own Google account and files the user saves themselves aren't "collection". |
| 10 | ✅ **Done** | **AI voicemail is on-device only.** Android's speech recogniser (Android 13+) plus rule-based summaries. No network, no API key, off by default. It uses the existing RECORD_AUDIO permission, because Android's recogniser requires it even for audio files. | The policy and Data safety are updated. When fixing #3, ask for RECORD_AUDIO in context for **either** feature: when Auto call recording **or** voicemail transcription is turned on, with wording that fits that feature ("Android needs the microphone permission to turn voicemail into text on your phone. The microphone isn't used."). |
| 11 | Low | **No in-app open-source licences screen.** The OFL texts are in `assets/licenses`, which satisfies the OFL, but libphonenumber, Retrofit, Gson and AndroidX (Apache 2.0) aren't credited in the UI. | Add a "Licences" row in Settings that lists them. Not a Play requirement. |
| 12 | Low | **Call recording on Android 10+ usually captures only your own voice** (VOICE_COMMUNICATION/MIC source), unless the phone is on speaker. If the listing promises "record both sides", users will complain and reviewers may call it misleading. | The listing below says "records your calls through the microphone" and suggests using the speaker for both sides. |
| 13 | **Blocker** | **The Nothing Glyph SDK forbids commercial use without written permission.** `app/libs/glyph-matrix-sdk-2.0.aar` (EULA in `assets/licenses/GlyphMatrixSDK-EULA.md`) says commercial use is "strictly prohibited" without Nothing's written permission. A public Play release is distribution, and "free" doesn't clearly make it non-commercial. The manifest also has `NothingKey="test"` and the `com.nothing.ketchum.permission.ENABLE` permission. The user approved the SDK for personal, non-commercial use only. | Choose one before uploading: **(a)** email GDKsupport@nothing.tech and get written permission (and a production NothingKey, although targeting API 36 per fix #1 removes the key requirement), or **(b)** keep Glyph out of the Play build: a `play` product flavour without the AAR, the permission and the meta-data, or remove the feature. Option (b) is the quickest. Either way, never write "Glyph" or "Nothing" in the listing. |

### Features added after this audit (re-check before submission)

These sessions were still working when this audit was written. Re-read the manifest diff and update the privacy policy and Data safety when they finish:
- **Glyph lights:** ⛔ see **fix #13** (SDK licence). Also keep "Glyph" and "Nothing" out of the listing, screenshots and keywords.
- **Backup & restore:** ✅ checked. Encrypted Auto Backup to the user's own Google account, plus a manual export to a file the user picks. Data safety doesn't change; the policy is updated (see fix #9).
- **VIP / DND / reminders:** ✅ checked. `SCHEDULE_EXACT_ALARM` is used only after the user grants "Alarms & reminders" (Settings → Reminders → Allow exact times); otherwise the app uses `setAndAllowWhileIdle`. `USE_EXACT_ALARM` is deliberately not declared. `RECEIVE_BOOT_COMPLETED` restores reminders. Quiet hours use `CallScreeningService.setSilenceCall` and read `currentInterruptionFilter`, with no `ACCESS_NOTIFICATION_POLICY`. Two things to check by hand: quiet hours must not silence emergency callbacks or repeat callers if the user expects them, and the boot receiver must stay limited to the system boot actions.
- **Emergency calls:** make sure emergency numbers are always passed to Telecom, never blocked by block rules or the screening service, and never recorded.
- **AI voicemail:** ✅ on-device only (fix #10).
- **WhatsApp shortcuts:** covered in the permission table below.

Not a Play problem but worth knowing: the voicemail note says MainActivity ignores numbers in `ACTION_DIAL` / `tel:` intents. Play doesn't check this, but default-dialer reviewers sometimes try "tap a phone number on a web page".

## 3. Technical release checklist

- [ ] **Target API 36** (fix #1). Play has required it for new apps since 31 Aug 2026. minSdk 26 is fine.
- [ ] **versionCode / versionName:** start with `versionCode = 1`, `versionName = "1.0.0"`. Every upload, including internal testing, needs a higher versionCode, so increase it by 1 for each upload. Consider `versionName` = semver.
- [ ] **Build the bundle:** ask the Release build session for `:app:bundleRelease`. Output: `app/build/outputs/bundle/release/app-release.aab`. Don't run Gradle in any other session.
- [ ] **Play App Signing:** when creating the app, choose "Use Google-generated key" (recommended). The existing `nodialer-release.jks` then becomes the **upload key**. Keep the .jks and `keystore.properties` backed up offline. Both are git-ignored (checked). If the upload key is lost, Google can reset it, but the account owner has to ask.
- [ ] **Shrinker mapping file:** R8 is on (`isMinifyEnabled = true`, `isShrinkResources = true`). An `.aab` built by AGP already contains the R8 mapping (`BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map`), and Play deobfuscates crash reports with it automatically. If you ever upload an APK, upload `app/build/outputs/mapping/release/mapping.txt` by hand (App bundle explorer → Downloads → ReTrace mapping file). Keep a copy of `mapping.txt` for each versionCode.
- [ ] **Native debug symbols:** none. libphonenumber is pure Java, so ignore the warning if Play shows one.
- [ ] **Release lint is turned off** (`checkReleaseBuilds = false` because of a lint crash). Run `:app:lint` by hand once before the first upload (Release build session only).
- [ ] **Merged manifest check:** no `AD_ID`, no unexpected permissions from Glance or WorkManager. WorkManager adds `RECEIVE_BOOT_COMPLETED` and `ACCESS_NETWORK_STATE`; both are normal permissions and fine.
- [ ] **Pre-launch report:** the robo crawler can't act as the default dialer. Expect "Set as default" screens. That's fine.
- [ ] **Testing track:** new **personal** developer accounts (created after Nov 2023) must run a **closed test with at least 12 testers for 14 continuous days** before production access. If this account is personal, plan that time in. Organisation accounts are exempt.
- [ ] **Store assets:** 512×512 icon, 1024×500 feature graphic, 2–8 phone screenshots (see [store-listing.md](store-listing.md)).
- [ ] **App content page:** privacy policy URL, ads = No, app access, content rating, target audience, data safety, government app = No, financial features = No, health = No, permissions (call log), foreground services, full-screen intent.
- [ ] **App access:** the reviewer has to make NoDialer the default dialer. Explain this under "App access → All or some functionality is restricted" with steps: install → open → tap "Set as default" → allow. No login is needed.
